# Objective
## Documentation-Driven Roadmap Execution and Progress Tracking for Initial Phases

---

## Role
You are a project execution specialist. Approach this objective with a focus on structured implementation, documentation adherence, and meticulous progress tracking.

---

## Description
The purpose is to begin executing a project roadmap by following its defined phases in strict sequential order, starting with Phase 1 and Phase 2. All tasks and implementation details must be derived exclusively from the documentation files located in the project's docs folder. These documents serve as the single source of truth for what needs to be built and how. Upon the completion of both phases, a progress tracking file must be created to record the implementation status. This ensures a documented, auditable trail of project advancement tied directly to the roadmap.

---

## Primary Objective
Execute Phase 1 and Phase 2 of the project roadmap sequentially, using the documentation in the docs folder as the authoritative source for all tasks, and create a roadmap-progress.md file in the same folder after the phases are implemented.

---

## Secondary Objectives
- Locate and read all relevant documentation files within the docs folder to inform task execution.
- Complete Phase 1 in full before beginning Phase 2.
- Generate a roadmap-progress.md file after finishing both phases to track completion status.

---

## Constraints
- All tasks and implementation details must be based solely on the content found in the docs folder and the roadmap.
- Phases must be implemented sequentially; Phase 2 must not begin until Phase 1 is complete.

---

## Context & Dependencies
- The docs folder contains the documentation files that are the primary information source for all tasks.
- A roadmap file exists that defines the phases to be followed.

---

## Supporting Tasks

### Documentation Review
- Read all files within the docs folder to understand the project requirements and implementation details.
- Read the roadmap file to understand the structure and requirements of Phase 1 and Phase 2.

### Phase Execution
- [Tag: Sequential] Implement Phase 1 as defined in the roadmap, using only information from the docs folder.
- [Tag: Sequential] After Phase 1 is complete, implement Phase 2 as defined in the roadmap, using only information from the docs folder.

### Progress Tracking
- After completing both phases, create a file named roadmap-progress.md in the docs folder.
- Record the completion status of Phase 1 and Phase 2 within roadmap-progress.md.
