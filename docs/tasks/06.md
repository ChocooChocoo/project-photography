# Objective

## Reset and Seed Fresh Database Data While Preserving Users and Locations

---

## Role

You are a database engineer responsible for resetting, seeding, and validating relational database data while preserving specified records and maintaining valid relationships between tables.

---

## Description

Reset the database and populate it with entirely fresh seed data while preserving all existing records in the `users` and `locations` tables. All other applicable tables must receive newly generated records with new titles, names, profiles, relationships, and related values. Existing user records must not be replaced or deleted; any required user records must be added alongside them. The seeded data must not contain images, videos, files, media paths, redirection URLs, or references to media-related resources.

---

## Primary Objective

Create and execute a new database seeder that replaces the data in all applicable tables with fresh, internally consistent records while preserving the existing `users` and `locations` tables.

---

## Secondary Objectives

* Add new user records when required without deleting, replacing, or modifying existing users.
* Preserve all existing location records and use them where location relationships are required.
* Populate every applicable non-media table with fresh data.
* Create at least 10 studios with distinct owners and complete staffing relationships.
* Exclude all images, videos, files, media paths, and other media-related data from the seed process.
* Compile all implemented tasks into a single Markdown document and include it in the prompt output.

---

## Success Criteria

* A new database seeder is created and can reset and repopulate all applicable tables.
* Existing records in the `users` table remain intact.
* Existing records in the `locations` table remain intact.
* Any new users are added without replacing existing users.
* All other applicable tables contain newly generated data.
* At least 10 studios are created.
* Each studio has a different studio owner.
* Each studio owner has 10 photographers associated with their studio.
* Each studio includes any additional employee or staff records required by the existing database structure.
* Seeded records maintain valid relationships across all populated tables.
* No seeded record contains an image, video, file, media path, media URL, redirection path, or other media reference.
* Media-related tables remain empty or are excluded from the seeding process.
* All implemented work is documented in one Markdown file included in the prompt output.

---

## Constraints

* Do not delete, replace, or reset existing records in the `users` table.
* Do not delete, replace, or reset existing records in the `locations` table.
* New user records may be added, but existing user records must remain unchanged.
* Do not seed the media table or any table whose records require images, videos, files, or other media.
* Do not create placeholder media paths, URLs, redirections, filenames, or file references.
* Seed only simple, non-media data.
* Create a minimum of 10 studios.
* Assign a unique owner to each studio.
* Associate 10 photographers with each studio owner.

---

## Out of Scope

* Replacing or removing existing users.
* Replacing or removing existing locations.
* Creating or attaching images, videos, documents, files, or other media.
* Populating media tables.
* Adding placeholder media URLs, storage paths, redirects, or file references.

---

## Context & Dependencies

* The database already contains user and location records that must be preserved.
* Existing profile records currently do not contain images.
* The new seed data must follow the database’s current table structure and relationships.
* New studios, owners, photographers, employees, and staff must be connected through the appropriate existing database relationships.

---

## Stakeholders

* Existing users whose database records must be preserved.
* Studio owners represented in the newly seeded data.
* Photographers, employees, and staff associated with each newly seeded studio.

---

## Supporting Tasks

### Database Reset

* Exclude the `users` and `locations` tables from destructive reset operations.
* Clear all existing data from the remaining applicable non-media tables.
* Respect foreign-key dependencies and the required deletion or truncation order.
* Ensure the reset does not remove or modify preserved user and location records.

### User and Location Preservation

* Retain every existing record in the `users` table.
* Add new user records only when they are required for the new seed relationships.
* Retain every existing record in the `locations` table.
* Reuse preserved location records when seeded entities require location associations.

### Fresh Data Generation

* Generate new names, titles, profiles, labels, and other applicable values for every newly seeded record.
* Populate every applicable table with data that conforms to its schema and relationships.
* Ensure the newly generated data is distinct from the records removed during the reset.
* Maintain referential integrity between all seeded records.

### Studio and Staffing Data

* Create at least 10 new studios.
* Assign a different studio owner to each studio.
* Create or associate 10 photographers for every studio owner.
* Create any additional employees, staff members, or related personnel required by the existing schema.
* Connect each owner, photographer, employee, and staff member to the correct studio.

### Media Exclusion

* Do not create records in media-specific tables.
* Do not populate image, video, file, attachment, thumbnail, avatar, or similar media fields.
* Do not add media URLs, storage paths, redirect paths, filenames, or placeholder references.
* Ensure seeded profiles and entities remain valid without media attachments.

### Documentation

* Compile all implemented reset and seeding tasks into one document.
* Format the document as Markdown.
* Include the Markdown document directly in the prompt output.

---

## Detailed Breakdown

### Preserved Tables

The `users` and `locations` tables must be excluded from the database reset. Existing records in these tables must remain available and unchanged after the seeder runs. When additional users are required to represent new studio owners, photographers, employees, or staff, those users must be inserted as new records rather than replacing existing ones.

### Reset Scope

All applicable tables other than `users`, `locations`, and media-related tables must be cleared before fresh records are inserted. The reset process must account for foreign-key relationships so that dependent records are removed safely and the preserved tables are not affected.

### Studio Structure

The seed process must create a minimum of 10 studios. Every studio must have its own distinct owner, and each owner must be associated with 10 photographers. Additional employee or staff records must also be created when corresponding tables or relationships exist in the database.

### Data Freshness

All newly seeded records must use fresh values, including new names, titles, profile details, and other applicable fields. The records must conform to the existing schema and remain logically consistent across related tables.

### Media-Free Records

No seeded entity may depend on an image, video, file, or other media resource. Media fields must remain empty or unset where the schema permits, and no placeholder URLs, file paths, redirects, attachment references, or media records may be generated.

### Final Documentation

The completed implementation must be summarized in a single Markdown document. The document must describe the reset behavior, preserved tables, generated records, studio and staffing structure, media exclusions, and all other implemented seeding tasks.
