# 05 — Restore and Verify System-Wide Media Display

**Status:** Complete. 65/65 tests pass. Media verified end to end on localhost.

---

## 1. Diagnostic Phase

### 1.1 Symlink scan — result: no symlink exists

The task assumed an active symbolic link was the cause. Three independent checks say otherwise.

| Check | Command | Result |
|---|---|---|
| Windows reparse point | `Get-Item public\storage` | `Mode: d-----`, `LinkType:` *(empty)* — plain directory |
| Directory-level scan | `cmd /c "dir /AL public"` | `File Not Found` — zero links under `public/` |
| Repo-level scan | `git ls-files -s \| awk '$1=="120000"'` | empty — no symlink blobs tracked anywhere |

**There was nothing to remove.** The remediation phase was therefore not "delete a symlink" but "remove the dependency on one".

### 1.2 Actual root cause

Commit `e980c99` — *"fix: restore gallery asset delivery…"* — recreated `public/storage` as a Windows junction pointing at `storage/app/public`. Git does not record junctions as links; it walked into the junction and committed its **contents** as 229 real file blobs.

The junction is long gone. Every clone and every deploy now checks out `public/storage` as an ordinary directory containing a frozen April-2026 snapshot.

That split the media path in two:

| | Path | Call sites |
|---|---|---|
| Runtime **writes** | `storage/app/public/` | 20 × `Storage::disk('public')`, 12 × `store()`/`storeAs()` |
| Web server **reads** | `public/storage/` | 60 × `asset('storage/…')` |

Nothing bridged the two. Consequences:

- Seeded demo media rendered fine — masking the bug.
- **Every upload made after deploy returned 404.** This is the reported symptom.
- The repo carried every image twice (229 files in each tree, confirmed byte-identical via `sha256sum`).
- `php artisan storage:link` on a fresh deploy **fails**, because `public/storage` already exists as a real directory.

### 1.3 Second defect found during the scan

`config/filesystems.php` had `'serve' => true` on the **private** `local` disk. Laravel turns that into a real route:

```
GET|HEAD  storage/{path} ......... storage.local
```

It sits directly on the media URL namespace and resolves against `storage/app/private/`. Harmless only because that directory happens to be empty — the moment anything is written there it becomes publicly downloadable at `/storage/...` with no authentication. Fixed (§2.1).

### 1.4 Ruled out — verified working, left untouched

- **Upload disk targeting.** All 12 `store()`/`storeAs()` calls pass `'public'` explicitly. Zero bare `Storage::` calls that would silently fall through to the default disk. `storage/app/private/` is empty.
- **Image corruption.** `.gitattributes` carried `* text=auto eol=lf` across 229 committed binaries. Auto-detection held: working-tree size equals blob size (178380 == 178380) and PNG magic `89 50 4e 47` is intact. Hardened anyway (§2.4).
- **Frontend build.** No `@vite` in any view; the UI serves 609 tracked static files from `public/assets/`. Unaffected.
- **Web server config.** `public/.htaccess` already passes existing files through untouched (`RewriteCond %{REQUEST_FILENAME} !-f`), so a real directory serves correctly.
- **Media type coverage.** Accepted types are `jpg/jpeg/png/gif`, `pdf`, `doc/docx`, `xls/xlsx` (no video). All flow through the same `asset('storage/…')` path, so one fix covers every type.

## 2. Implementation Phase

Approach: point the `public` disk at the directory the web server already serves, and remove the symlink concept from the project entirely. No symlink, no deploy hook, no artisan step — identical behavior on Windows localhost, `php artisan serve`, Linux, and shared hosting.

### 2.1 `config/filesystems.php` — repoint the disk

```php
'local' => [
    'driver' => 'local',
    'root' => storage_path('app/private'),
    // Off deliberately: `serve => true` registers a GET /storage/{path}
    // route that reads from this private disk, shadowing the public
    // media namespace. Nothing serves files from here.
    'serve' => false,
    ...
],

'public' => [
    'driver' => 'local',
    'root' => public_path('storage'),   // was storage_path('app/public')
    'url' => rtrim(env('APP_URL'), '/').'/storage',
    'visibility' => 'public',
    ...
],

'links' => [
    //
],
```

**Zero application code changed.** All `Storage::disk('public')` operations (`put`, `exists`, `delete`, `makeDirectory`) and all `store*()` calls are root-relative and followed the new root automatically. All 60 `asset('storage/'.$path)` reads already pointed at it. DB-stored paths stay relative (`brand-logos/xxx.png`) — no data migration needed.

### 2.2 Removed the duplicate tree

Confirmed identical by content hash before deleting (both trees: `fa68e25c780eb2ca…`), so `public/storage` was already the complete copy.

```bash
git rm -r --cached storage/app/public && rm -rf storage/app/public
```

229 duplicate blobs dropped from the repo. All remain recoverable from git history.

### 2.3 `.gitignore` — stop re-tracking it

```diff
 # Storage
+# The "public" disk writes to public/storage (tracked), not storage/app/public.
 /storage/*
 !/storage/app
 /storage/app/*
-!/storage/app/public
```

`public/storage` stays tracked — that is what ships the seeded demo media to production.

### 2.4 `.gitattributes` — explicit binary handling

Added ahead of the existing `diff=` rules, so `* text=auto eol=lf` can never rewrite committed media:

```
*.png  binary
*.jpg  binary
*.jpeg binary
*.gif  binary
*.webp binary
*.ico  binary
*.pdf  binary
*.doc  binary
*.docx binary
*.xls  binary
*.xlsx binary
```

### 2.5 `tests/Feature/MediaStorageTest.php` — regression guard

Three assertions that fail if the invariant is ever broken again:

1. `config('filesystems.disks.public.root') === public_path('storage')` — write path is the served path.
2. `config('filesystems.links') === []` — delivery never depends on `storage:link`.
3. Round trip: `Storage::disk('public')->put()` → assert the file exists at `public_path('storage/…')` → `delete()` → assert it is gone.

## 4. Production Deployment Checklist

- [ ] **`APP_URL` must be the real scheme + domain.** `asset()` builds every media URL from it. A stale `http://localhost` breaks all 60 read sites, and `http://` on an HTTPS host gets blocked as mixed content. This is the single most likely cause of "works locally, broken in production" after this fix.
- [ ] `APP_ENV=production`, `APP_DEBUG=false`.
- [ ] `php artisan config:clear` after editing `.env` — `APP_URL` is baked into cached config.
- [ ] Web root points at `public/`.
- [ ] `public/storage` is writable by the PHP user (`755` dirs, `644` files, owned by the web user).
- [ ] **Do not run `php artisan storage:link`.** It is no longer part of deployment. If a `public/storage` symlink exists on the server from an earlier deploy, **delete it before deploying** — a symlink there would shadow the real directory and reintroduce the bug.

## 5. Findings Flagged, Not Fixed

Both predate this task and are untouched by this change.

### 5.1 Unauthenticated access to identity documents — *security*

`public/storage/valid-ids/` (government IDs) and `public/storage/studio_documents/` are fetchable by URL by anyone who guesses a filename. No authentication. They are also committed to git.

Linked from:
- `resources/views/admin/pending-studios.blade.php:690`
- `resources/views/admin/view-studios.blade.php:605`
- `resources/views/owner/view-studio.blade.php:739`
- `app/Http/Controllers/StudioPhotographer/AssignedStudioController.php:270`

This change neither creates nor worsens the exposure — the files were already in the webroot and already in git. Deferred by decision to keep this task scoped to media display.

**Recommended remediation:** move both directories to the `local` (private) disk, add an auth-gated streaming route (`/documents/{path}` returning `Storage::disk('local')->response()`), update the four call sites above, and purge the files from git history.

### 5.2 i18n translation files 404 — *pre-existing theme bug*

Console on `/auth/login`:

```
Translation load error: SyntaxError: Unexpected token '<', "<!DOCTYPE "... is not valid JSON
```

`I18nManager` in `public/assets/js/app.js` fetches a **relative** path, `assets/data/translations/en.json`. On `/auth/login` that resolves to `/auth/assets/data/translations/en.json`, which 404s to the HTML fallback and fails to parse as JSON. The files exist at `public/assets/data/translations/`.

Not media, and the fix lives inside a minified vendor theme bundle — editing that by hand is not worth it. Correct fix is to make `langPath` absolute (`/assets/data/translations/`) at the theme source and rebuild.
