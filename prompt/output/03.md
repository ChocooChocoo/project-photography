### Relational integrity

Twelve hardcoded `location_id` integers across `MultiStudioBundleSeeder` and `FreelancerMarketplaceBundleSeeder` now resolve by municipality name through `SeedSupport::locationId()`, which throws rather than writing a dangling key.

This was a real defect, not a cosmetic one: `tbl_locations` was seeded *last*, but `MultiStudioBundleSeeder` ran fourth and wrote `location_id => 6 / 7 / 2` into `tbl_studios`, `tbl_users`, and `tbl_studio_schedules`. `tbl_studio_schedules.location_id` is a non-nullable constrained FK, so a fresh MySQL seed hit a constraint violation against an empty table. It went unnoticed because the test suite uses SQLite in-memory.

New `php artisan db:verify-seed` reads every FK from `information_schema.KEY_COLUMN_USAGE`, left-joins each child to its parent, and reports dangling references. It also asserts the task invariants: Cavite-only locations, `@gmail.com` users, verified users, and that each studio's `barangay` string is a member of its own location's barangay list.

### Table cleanup

Dropped `tbl_online_gallery` — zero references in `app/`, `routes/`, `resources/views/`, or the seeder chain, and no Eloquent model. Superseded by `tbl_studio_online_gallery` and `tbl_freelancer_online_gallery`, both of which have models, controllers, and seed data. `down()` recreates it.

Also removed `2026_02_04_160453_create_tbl_studio_photographers_table_v2.php`, byte-identical to the migration 15 minutes before it and guaranteed to fail on any fresh run.

Every other table survived the audit. `tbl_studio_members` (2 controllers), `tbl_employee_payroll` (2 form requests + model), the `tbl_chatbot_*` set, and all `tbl_procurement_*` tables are live. `pvt_studio_photographers` had already been dropped by an earlier migration.

### Queue tables

`jobs`, `job_batches`, `failed_jobs` added from the framework stubs. `.env` sets `QUEUE_CONNECTION=database` and `composer dev` runs `queue:listen`, but no migration for these ever existed. Names match `config/queue.php` unchanged; no `tbl_` prefix, consistent with `migrations` as framework infrastructure.

## Migration repairs found along the way

The schema had been maintained by hand on the live database, so several changes never became migrations. Each of these blocked `migrate:fresh` and had to be fixed before any seeding could be verified.

| Problem | Fix |
|---|---|
| `tbl_studios.location_id/street/barangay` never migrated; the next migration's `after('barangay')` failed | `2026_01_28_151802_add_address_to_tbl_studios_table.php` |
| `tbl_payments` Stripe identifiers never migrated | `2026_02_24_095335_add_stripe_columns_to_tbl_payments_table.php` (keeps both PayMongo and Stripe columns — the controllers use both) |
| `tbl_services`: `service_description`/`status` dropped and `service_name` widened to text on the live DB only | `2026_02_07_090000_normalize_tbl_services_columns.php` |
| `tbl_freelancer_ratings.freelancer_id` FK referenced `tbl_freelancers.user_id`, which has no unique key | Repointed at `tbl_users.id` — the column holds a user id, matching `updateAggregate()` and `booking.provider_id` |
| `add_category_id_to_tbl_freelancer_services` duplicated a column the create migration already adds | Guarded with `Schema::hasColumn` |
| Duplicate `create_tbl_studio_photographers_table_v2` | Deleted |

## Notes

**Pint.** `./vendor/bin/pint` had never been run on this repository and reformats 292 files. Only the files touched by this task were kept formatted; the other 270 were reverted so the diff stays reviewable. Running Pint repo-wide is worth its own commit.

**Queue tables are empty by design.** Nothing in `app/` implements `ShouldQueue` yet, so nothing is dispatched. The tables exist so `queue:listen` stops crashing and so the first queued job has somewhere to land. Verified: `Queue::pushRaw` writes correctly and `queue:work --stop-when-empty` exits 0.

**Pre-existing console errors.** The admin pages log `Translation load error` — the vendor UBOLD theme's `I18nManager` fetching `assets/data/translations/en.json`, which 404s to the HTML error page. Unrelated to seeding, untouched.

**Barangay data.** Sourced from PhilAtlas, which mirrors PSA/PSGC. Counts total exactly 829, the published figure for Cavite. `SeedIntegrityTest` locks the LGU and barangay totals, so a future edit that drops or duplicates entries fails the suite.
