# Objective
## Comprehensive Database Seeder Reset with Cavite-Localized Relational Data

---

## Role
You are a backend/database engineer specializing in Laravel database migrations and seeding. Approach this objective with a focus on data integrity, relational consistency, and clean-slate initialization.

---

## Description
The objective is to reset the application's database to a fresh state and populate it with an entirely new set of seed data. Every table must receive new records, and all relationships between tables must be properly established and linked through the seeding process. Existing user data and all other records are to be replaced completely. The seeding must produce a fully functional, internally consistent dataset that supports all system processes from the moment of initialization.

---

## Primary Objective
Generate a complete set of fresh, relational seed data for every table in the system, ensuring all inter-table relationships are correctly established, while dropping any tables that are unused or non-essential to overall system processes.

---

## Secondary Objectives
- Populate user records with realistic full names, `@gmail.com` email addresses, pre-verified status, and a uniform default password of `Password_123`.
- Restrict all location data in `tbl_locations` exclusively to municipalities, cities, and barangays within the province of Cavite, Philippines.
- Identify and remove any database tables that are unnecessary, unused, or irrelevant to the system's core processes.

---

## Success Criteria
- Every table required for system operation contains newly seeded records.
- All foreign key and relational linkages between tables are valid and intact.
- All user accounts are created with realistic names, `@gmail.com` emails, verified status, and the password `Password_123`.
- The `tbl_locations` table contains only Cavite province locations, covering all municipalities, cities, and barangays, with no locations outside Cavite.
- Any non-essential or unused tables have been successfully dropped from the database.

---

## Constraints
- User emails must exclusively use the `@gmail.com` domain.
- All user passwords must be set to the literal string `Password_123`.
- All seeded location data must be confined to the province of Cavite, Philippines.
- The seeder must operate as a migration seeder, designed for fresh database initialization.

---

## Context & Dependencies
- The system currently contains existing user data and other production or legacy records that are to be completely replaced.
- An existing database schema with defined tables and relationships is in place; the seeder must align with this schema after unused tables are dropped.

---

## Supporting Tasks

### Database Cleanup
- Audit all existing tables to identify those that are unused or non-essential to the overall system process.
- Drop identified unnecessary tables from the database.

### User Seeding
- Seed the users table with realistic full names.
- Set every user's email to an `@gmail.com` address.
- Mark all seeded users as verified.
- Set the password for all users to `Password_123`.

### Location Seeding
- Populate `tbl_locations` with a complete hierarchy of all municipalities, cities, and barangays within Cavite, Philippines.
- Ensure no location records reference areas outside Cavite.

### Relational Data Seeding
- Seed all remaining operational tables with fresh data.
- Ensure every seeded record maintains correct foreign key relationships to corresponding records in related tables.
- Validate that all relationships across the dataset are properly linked and consistent.

## Detailed Breakdown

### User Account Specifications
Every seeded user record must contain a realistic first name and last name combination. The email address for each user must be constructed using the `@gmail.com` domain exclusively, as these accounts serve migration and development purposes only. All users must be set to a verified state immediately upon creation, bypassing any email verification workflows. The plain-text equivalent of the password field for every account must be set to `Password_123`, with appropriate hashing applied according to the application's authentication mechanism.

### Location Data Scope
The `tbl_locations` table must contain only geographical entries within the province of Cavite, Philippines. This includes every municipality, every component city, and all barangays under each municipality and city. No entries referencing other provinces, regions, or countries are permitted. The seeding must produce a complete and accurate hierarchy that reflects the actual administrative divisions of Cavite.

### Table Cleanup Criteria
A table qualifies for removal if it meets any of the following conditions: it is not referenced by any application process, it contains only historical or deprecated data with no active system use, or it is orphaned with no relationships to other operational tables. The determination must be made by analyzing the current codebase and system workflows to confirm non-usage before dropping.

### Relational Integrity Requirement
Every seed record inserted into any table that contains foreign keys must reference a valid, existing primary key in the related parent table. Seeding order must respect dependency chains so that parent records are created before child records. After all seeding operations complete, a consistency check must confirm that no orphaned or dangling references exist anywhere in the dataset.
